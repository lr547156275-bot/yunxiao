# third.cc 使用手册

本文档说明如何编写 `config.txt`、`topology.txt`、`flow.txt`、`trace.txt` 等输入文件，用 `simulation/scratch/third.cc` 搭建自己的仿真场景。

## 运行方式

通常在 `simulation` 目录下运行：

```bash
./waf --run "scratch/third mix/config.txt"
```

其中 `mix/config.txt` 是配置文件路径。`third.cc` 会从这个配置文件中继续读取 topology、flow、trace 文件路径。

如果没有传配置文件，程序会打印：

```text
Error: require a config file
```

## 输入文件总览

一个场景通常至少需要四个输入文件：

```text
config.txt    总配置文件
topology.txt  拓扑文件
flow.txt      流量文件
trace.txt     需要开启 trace 的节点列表
```

`config.txt` 中用这些字段指定它们的位置：

```text
TOPOLOGY_FILE mix/topology.txt
FLOW_FILE mix/flow.txt
TRACE_FILE mix/trace.txt
```

路径是相对运行目录的。若你在 `simulation` 目录运行，则 `mix/topology.txt` 指的是：

```text
simulation/mix/topology.txt
```

## topology.txt 格式

### 基本格式

```text
node_num switch_num link_num
switch_id_0 switch_id_1 ... switch_id_{switch_num-1}
src_0 dst_0 data_rate_0 link_delay_0 error_rate_0
src_1 dst_1 data_rate_1 link_delay_1 error_rate_1
...
src_{link_num-1} dst_{link_num-1} data_rate link_delay error_rate
```

第一行：

```text
node_num    节点总数，节点编号为 0 到 node_num-1
switch_num  switch 数量
link_num    链路数量
```

第二部分读取 `switch_num` 个整数，表示哪些 node 是 switch。没出现在 switch 列表里的节点都会被当作 host。

后面读取 `link_num` 条链路，每条链路包含：

```text
src dst data_rate link_delay error_rate
```

字段含义：

- `src`：链路一端节点编号。
- `dst`：链路另一端节点编号。
- `data_rate`：链路速率，例如 `25Gbps`、`100Gbps`。
- `link_delay`：链路传播时延，例如 `0.001ms`、`1us`。
- `error_rate`：这条链路的按包错误率。`0` 表示不额外设置单链路错误率。

### 简单例子：2 个 host + 1 个 switch

拓扑：

```text
H1(node 0) --- S(node 2) --- H2(node 1)
```

`topology.txt`：

```text
3 1 2
2
0 2 100Gbps 1us 0
2 1 100Gbps 1us 0
```

解释：

- 总共 3 个节点：0、1、2。
- 其中 1 个 switch：node 2。
- 有 2 条链路：
  - node 0 到 node 2。
  - node 2 到 node 1。

所以 node 0 和 node 1 是 host，node 2 是 switch。

### 多 switch 例子：3-hop 路径

拓扑：

```text
H1(0) --- S1(2) --- S2(3) --- S3(4) --- H2(1)
```

`topology.txt`：

```text
5 3 4
2 3 4
0 2 100Gbps 1us 0
2 3 100Gbps 1us 0
3 4 100Gbps 1us 0
4 1 100Gbps 1us 0
```

解释：

- 总共 5 个节点。
- switch 是 2、3、4。
- host 是 0、1。
- 有 4 条链路。

### 注意事项

`third.cc` 只会读取 `link_num` 条链路。即使文件后面还有多余行，也不会作为链路使用。

链路是按双向记录的。你只需要写一行：

```text
0 2 100Gbps 1us 0
```

代码会自动在 `nbr2if[0][2]` 和 `nbr2if[2][0]` 中记录两个方向。

## flow.txt 格式

### 基本格式

```text
flow_num
src dst pg dport maxPacketCount start_time
src dst pg dport maxPacketCount start_time
...
```

第一行：

```text
flow_num
```

表示要读取多少条 flow。代码只会读取 `flow_num` 条，即使文件后面还有更多行。

每条 flow 的字段：

```text
src dst pg dport maxPacketCount start_time
```

含义：

- `src`：源 host 节点编号，必须是 host。
- `dst`：目的 host 节点编号，必须是 host。
- `pg`：priority group，优先级组，会影响使用哪个队列。
- `dport`：目的端口。
- `maxPacketCount`：流大小，代码中作为 RDMA client 的发送总量使用，单位按项目命名更接近 byte。
- `start_time`：flow 开始时间，单位是秒。

启动 flow 时，源端口由程序自动分配。每个 host pair 从 `10000` 开始递增：

```text
第一条 src->dst flow 使用 sport 10000
第二条 src->dst flow 使用 sport 10001
```

### 简单例子

```text
2
0 1 3 100 2000000 0.1
0 1 3 100 5000000 0.2
```

含义：

- 总共 2 条 flow。
- 第一条从 host 0 发到 host 1，优先级组 3，目的端口 100，大小 2,000,000，0.1 秒开始。
- 第二条同样从 0 到 1，大小 5,000,000，0.2 秒开始。

### 同时启动多条 flow

如果多条 flow 的 `start_time` 相同，`ScheduleFlowInputs()` 会在同一次调度中连续启动它们。

例子：

```text
3
0 1 3 100 2000000 0.1
2 3 3 100 2000000 0.1
4 5 3 100 2000000 0.1
```

这三条 flow 都会在仿真时间 0.1 秒启动。

### 注意事项

`src` 和 `dst` 必须是 host。代码里有断言：

```cpp
NS_ASSERT(n.Get(flow_input.src)->GetNodeType() == 0 && n.Get(flow_input.dst)->GetNodeType() == 0);
```

如果把 switch 写成 flow 源或目的，程序会失败。

flow 文件最好按 `start_time` 从小到大排序。代码按文件顺序读取并调度下一条 flow，如果时间倒序，容易出现不符合预期的调度。

## trace.txt 格式

### 基本格式

```text
trace_num
node_id_0 node_id_1 ... node_id_{trace_num-1}
```

第一行是要开启 trace 的节点数量。后面读取 `trace_num` 个节点编号。

也可以每个节点单独一行：

```text
3
0
2
4
```

代码使用 `>>` 读取，所以换行和空格都可以作为分隔符。

### 作用

如果配置文件中：

```text
ENABLE_TRACE 1
```

则程序会对 trace 文件列出的节点启用 Qbb 包级 trace。记录事件包括：

- `MacRx`：收到包。
- `QbbEnqueue`：入队。
- `QbbDequeue`：出队。
- `QbbDrop`：丢包。
- `RdmaQpDequeue`：RDMA QP 出队。

输出写入：

```text
TRACE_OUTPUT_FILE
```

如果某个 node id 超过节点总数，代码会跳过它。

## config.txt 格式

配置文件是若干个 `KEY VALUE` 组合。顺序一般不重要，但路径类配置必须在后面打开文件前被读到。

最小常用模板：

```text
ENABLE_QCN 1
USE_DYNAMIC_PFC_THRESHOLD 1

PACKET_PAYLOAD_SIZE 1000

TOPOLOGY_FILE mix/topology.txt
FLOW_FILE mix/flow.txt
TRACE_FILE mix/trace.txt
TRACE_OUTPUT_FILE mix/trace.tr
FCT_OUTPUT_FILE mix/fct.txt
PFC_OUTPUT_FILE mix/pfc.txt

SIMULATOR_STOP_TIME 1.0

CC_MODE 3
ALPHA_RESUME_INTERVAL 1
RATE_DECREASE_INTERVAL 4
CLAMP_TARGET_RATE 0
RP_TIMER 900
EWMA_GAIN 0.00390625
FAST_RECOVERY_TIMES 1
RATE_AI 50Mb/s
RATE_HAI 100Mb/s
MIN_RATE 100Mb/s
DCTCP_RATE_AI 1000Mb/s

ERROR_RATE_PER_LINK 0
L2_CHUNK_SIZE 4000
L2_ACK_INTERVAL 1
L2_BACK_TO_ZERO 0

HAS_WIN 1
GLOBAL_T 1
VAR_WIN 1
FAST_REACT 1
U_TARGET 0.95
MI_THRESH 0
INT_MULTI 1
MULTI_RATE 0
SAMPLE_FEEDBACK 0
PINT_LOG_BASE 1.05
PINT_PROB 1.0

RATE_BOUND 1
ACK_HIGH_PRIO 0
LINK_DOWN 0 0 0
ENABLE_TRACE 1

KMAX_MAP 3 25000000000 400 50000000000 800 100000000000 1600
KMIN_MAP 3 25000000000 100 50000000000 200 100000000000 400
PMAX_MAP 3 25000000000 0.2 50000000000 0.2 100000000000 0.2
BUFFER_SIZE 32

QLEN_MON_FILE mix/qlen.txt
QLEN_MON_START 2000000000
QLEN_MON_END 2010000000
```

### 常用配置说明

`ENABLE_QCN`：是否启用 QCN/ECN 相关逻辑。`1` 表示启用，`0` 表示关闭。

`USE_DYNAMIC_PFC_THRESHOLD`：是否使用动态 PFC 阈值。

`PACKET_PAYLOAD_SIZE`：数据包 payload 大小，单位 byte。

`TOPOLOGY_FILE`：topology 文件路径。

`FLOW_FILE`：flow 文件路径。

`TRACE_FILE`：trace 节点列表文件路径。

`TRACE_OUTPUT_FILE`：包级 trace 输出文件。

`FCT_OUTPUT_FILE`：flow completion time 输出文件。

`PFC_OUTPUT_FILE`：PFC 事件输出文件。

`SIMULATOR_STOP_TIME`：仿真停止时间，单位秒。

`CC_MODE`：拥塞控制模式。

- `3`：HPCC。
- `7`：Timely。
- `10`：HPCC-PINT。

`ERROR_RATE_PER_LINK`：默认链路错误率。如果 topology 某条链路自己的 `error_rate > 0`，则优先使用该链路自己的错误率。

`HAS_WIN`：是否设置窗口。`1` 表示使用 BDP/maxBdp 窗口，`0` 表示窗口参数为 0。

`GLOBAL_T`：是否使用全局最大 RTT/BDP。`1` 表示使用全局 `maxRtt`/`maxBdp`，`0` 表示使用每对 host 自己的 RTT/BDP。

`INT_MULTI`：INT 中 bytes 和 qlen 的量化倍数。越大表示记录越粗，但范围更大。

`MULTI_RATE`：是否按多速率路径处理反馈。

`SAMPLE_FEEDBACK`：是否采样反馈。

`PINT_LOG_BASE`：PINT 对数量化底数。

`PINT_PROB`：PINT 采样概率或阈值。

`RATE_BOUND`：是否按拥塞控制计算出的速率限制 NIC 发包。

`ACK_HIGH_PRIO`：是否让 ACK/NACK 走高优先级队列。

`LINK_DOWN`：链路故障配置：

```text
LINK_DOWN link_down_time nodeA nodeB
```

如果 `link_down_time > 0`，程序会在：

```text
2 秒 + link_down_time 微秒
```

调用 `TakeDownLink(nodeA, nodeB)`。

`ENABLE_TRACE`：是否开启 trace 文件中指定节点的包级 trace。

`KMAX_MAP`、`KMIN_MAP`、`PMAX_MAP`：按链路速率配置 ECN 标记阈值和最大标记概率。

格式为：

```text
KMAX_MAP n rate_0 kmax_0 rate_1 kmax_1 ...
KMIN_MAP n rate_0 kmin_0 rate_1 kmin_1 ...
PMAX_MAP n rate_0 pmax_0 rate_1 pmax_1 ...
```

其中 rate 单位是 bit/s，例如：

```text
100000000000
```

表示 100Gbps。

`BUFFER_SIZE`：交换机总 buffer，单位 MB。

`QLEN_MON_FILE`：队列长度分布输出文件。

`QLEN_MON_START`：队列监控开始时间，单位 ns。

`QLEN_MON_END`：队列监控结束时间，单位 ns。

## 输出文件说明

### FCT 输出

`FCT_OUTPUT_FILE` 每条完成 flow 输出一行：

```text
sip dip sport dport size start_time fct standalone_fct
```

字段含义：

- `sip`：源 IP，十六进制。
- `dip`：目的 IP，十六进制。
- `sport`：源端口。
- `dport`：目的端口。
- `size`：流大小。
- `start_time`：开始时间，单位 ns。
- `fct`：实际完成时间，单位 ns。
- `standalone_fct`：无排队无拥塞情况下估算的理想 FCT，单位 ns。

### PFC 输出

`PFC_OUTPUT_FILE` 每个 PFC 事件输出：

```text
time node_id node_type if_index type
```

字段含义：

- `time`：事件时间，单位 ns。
- `node_id`：节点编号。
- `node_type`：`0` host，`1` switch。
- `if_index`：接口编号。
- `type`：PFC 事件类型，具体含义取决于 QbbNetDevice 触发 trace 时传入的值。

### 队列长度输出

`QLEN_MON_FILE` 会周期性输出队列长度分布。

格式大致为：

```text
time: 2000000000
switch_id port_id cnt0 cnt1 cnt2 ...
```

其中 `cnti` 表示该 switch 的该端口在采样期间队列长度落在第 `i` 个 1000-byte 桶里的次数。

例如：

```text
5 2 10 3 0 1
```

表示 switch 5 的 port 2：

- 0~999 bytes 出现 10 次。
- 1000~1999 bytes 出现 3 次。
- 2000~2999 bytes 出现 0 次。
- 3000~3999 bytes 出现 1 次。

## 从零搭一个最小场景

假设我们要模拟：

```text
host 0 --- switch 2 --- host 1
```

### 1. topology.txt

```text
3 1 2
2
0 2 100Gbps 1us 0
2 1 100Gbps 1us 0
```

### 2. flow.txt

```text
1
0 1 3 100 2000000 0.1
```

### 3. trace.txt

```text
3
0 1 2
```

### 4. config.txt

可以复制前面的最小常用模板，然后把路径改成自己的文件：

```text
TOPOLOGY_FILE my/topology.txt
FLOW_FILE my/flow.txt
TRACE_FILE my/trace.txt
TRACE_OUTPUT_FILE my/trace.tr
FCT_OUTPUT_FILE my/fct.txt
PFC_OUTPUT_FILE my/pfc.txt
QLEN_MON_FILE my/qlen.txt
SIMULATOR_STOP_TIME 1.0
```

### 5. 运行

在 `simulation` 目录下：

```bash
./waf --run "scratch/third my/config.txt"
```

## 常见坑

`flow_num`、`link_num`、`trace_num` 控制实际读取数量。文件后面多出来的行不会自动生效。

flow 的 `src` 和 `dst` 必须是 host，不能是 switch。

flow 文件建议按开始时间升序排列。

topology 中 switch 列表必须准确。没有列进 switch 列表的节点都会被当作 host。

`KMIN_MAP/KMAX_MAP/PMAX_MAP` 里的 rate 要和链路实际 bit/s 匹配。例如 `100Gbps` 对应 `100000000000`。如果没有对应项，ECN 阈值可能配置不完整。

路径要相对运行目录填写。通常从 `simulation` 目录运行，所以示例中使用 `mix/...`。

`QLEN_MON_START` 和 `QLEN_MON_END` 单位是 ns，而 `SIMULATOR_STOP_TIME` 和 flow 的 `start_time` 单位是秒。
