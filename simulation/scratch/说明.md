本文档说明 `simulation/scratch/third.cc` 的整体作用、主要数据结构和执行流程。这个文件是 HPCC 仿真的主入口脚本，负责把配置文件、拓扑文件、流量文件、trace 文件、Qbb 链路、交换机、RDMA 主机和 ns-3 事件调度串起来。

## 总体作用

`third.cc` 不是某一个协议的小模块，而是一场完整仿真的编排器。它主要完成这些事情：

1. 读取配置文件，设置拥塞控制、PFC、ECN、队列监控、输出文件等参数。
2. 读取拓扑文件，创建 host 和 switch。
3. 给节点安装 InternetStack，并给 host 分配业务 IP。
4. 根据拓扑逐条创建 Qbb 链路和 QbbNetDevice。
5. 构建邻接表 `nbr2if`，用于后续 BFS 路由计算。
6. 配置交换机 MMU、PFC headroom、ECN 阈值和 buffer。 
7. 给 host 安装 RDMA driver 和 RdmaHw。
8. 计算路由、RTT、BDP 和瓶颈带宽。
9. 调度 flow、链路故障、队列长度监控。
10. 运行 ns-3 仿真，输出 FCT、PFC、trace、队列长度分布等结果。

## 重要全局参数

文件开头定义了大量全局配置变量。它们大多会被配置文件覆盖。

`cc_mode` 表示拥塞控制模式。常见取值：

- `3`：HPCC，使用完整 INT。
- `7`：Timely，使用时间戳。
- `10`：HPCC-PINT，使用压缩 PINT。
- 其他值：通常不额外携带 INT 头。

`enable_qcn` 表示是否启用 QCN/ECN 相关逻辑。

`use_dynamic_pfc_threshold` 表示是否使用动态 PFC 阈值。

`packet_payload_size` 是数据包 payload 大小，单位 byte。

`pause_time` 是 PFC pause 时间。

`buffer_size` 是交换机 buffer 大小，配置文件中单位是 MB。

`qlen_mon_start`、`qlen_mon_end` 和 `qlen_mon_interval` 控制队列长度监控的时间窗口和采样间隔。

## 关键运行时结构

### `NodeContainer n`

保存所有节点。普通 host 使用 ns-3 原生 `Node` 创建，switch 使用自定义 `SwitchNode` 创建。

代码中约定：

```text
GetNodeType() == 0 表示 host
GetNodeType() == 1 表示 switch
```

### `Interface`

```cpp
struct Interface{
    uint32_t idx;
    bool up;
    uint64_t delay;
    uint64_t bw;
};
```

它描述某个节点到某个邻居节点的接口信息：

- `idx`：本节点上连接到邻居的 interface/device 编号。
- `up`：链路是否可用。
- `delay`：链路传播时延。
- `bw`：链路带宽，单位 bit/s。

### `nbr2if`

```cpp
map<Ptr<Node>, map<Ptr<Node>, Interface> > nbr2if;
```

这是拓扑邻接表。含义是：

```text
nbr2if[node][neighbor] = node 到 neighbor 这条边的信息
```

它在创建每条 Qbb 链路时填充，后面用于：

- `CalculateRoute()` 做 BFS。
- `SetRoutingEntries()` 把下一跳节点转换成出端口。
- `TakeDownLink()` 标记链路 down。

### `nextHop`

```cpp
map<Ptr<Node>, map<Ptr<Node>, vector<Ptr<Node> > > > nextHop;
```

含义是：

```text
nextHop[node][dst] = node 去 dst 的可选下一跳节点列表
```

它保存路由计算结果。如果存在多条等长最短路径，列表里会有多个下一跳，用于 ECMP。

### `pairDelay`、`c`、`pairBw`、`pairRtt`、`pairBdp`

这些表保存节点对之间的基础路径信息：

- `pairDelay[src][dst]`：传播时延总和。
- `pairTxDelay[src][dst]`：发送一个 payload 的序列化时延估计。
- `pairBw[src][dst]`：路径瓶颈带宽。
- `pairRtt[src][dst]`：基础 RTT。
- `pairBdp[src][dst]`：BDP。

它们主要用于 RDMA 窗口、base RTT 和 standalone FCT 计算。

### `serverAddress`

保存每个 host 的业务 IP。这个 IP 用于 RDMA flow 的源地址和目的地址。

链路上还会自动分配 `10.x.x.x` 这类普通 IP，但那些主要是为了 ns-3 InternetStack 连通性，业务流真正使用的是 `serverAddress`。

### `queue_result`

```cpp
map<uint32_t, map<uint32_t, QlenDistribution> > queue_result;
```

含义是：

```text
queue_result[switch_id][port_id] = 这个端口的队列长度分布
```

它不是实际队列，而是队列长度采样结果。`monitor_buffer()` 会周期性读取 switch MMU 中的 `egress_bytes[port][queue]`，累加为端口队列长度，然后按 `1000 bytes` 一个桶统计。

## 主要函数

### `ReadFlowInput()`

从 flow 文件读取下一条 flow：

```text
src dst pg dport maxPacketCount start_time
```

它只负责读入，不负责启动 flow。

### `ScheduleFlowInputs()`

在仿真时间到达 flow 的 `start_time` 时执行。它会：

1. 为当前 host pair 分配一个新的源端口。
2. 创建 `RdmaClientHelper`。
3. 在源 host 上安装应用。
4. 启动应用并创建 QP。
5. 继续读取下一条 flow。
6. 如果下一条 flow 的开始时间不同，就调度下一次执行。

同一时刻开始的多条 flow 会在同一次 `ScheduleFlowInputs()` 里连续启动。

### `qp_finish()`

一条 RDMA QP/flow 完成后触发。它会：

1. 根据 QP 的源/目的 IP 反查节点编号。
2. 计算基础 RTT、瓶颈带宽和 standalone FCT。
3. 输出 FCT 结果到 `FCT_OUTPUT_FILE`。
4. 删除接收端对应的 Rx QP 状态。

输出字段为：

```text
sip dip sport dport size start_time fct standalone_fct
```

### `QlenDistribution` 和 `monitor_buffer()`

`QlenDistribution` 是队列长度分布统计器。它把 byte 单位的队列长度除以 `1000`，得到 KB 桶编号：

```text
0~999 bytes      -> cnt[0]
1000~1999 bytes  -> cnt[1]
2000~2999 bytes  -> cnt[2]
```

`monitor_buffer()` 会遍历所有 switch 的所有端口，累加该端口所有优先级队列的 `egress_bytes`，并加入 `queue_result`。

### `CalculateRoute(host)`

以某个 host 为目的地，反向 BFS，计算所有节点到这个 host 的最短跳数下一跳。

它维护：

- `q`：BFS 待处理队列。只把 switch 放入队列继续扩展，避免 host 被当作中转节点。
- `dis`：节点到目的 host 的跳数，同时也作为 visited 标记。
- `delay`：路径传播时延。
- `txDelay`：路径发送时延估计。
- `bw`：路径瓶颈带宽。

核心语句：

```cpp
nextHop[next][host].push_back(now);
```

含义是：

```text
对于目的 host，节点 next 的一个可选下一跳是 now。
```

因为 BFS 是从目的 host 反向扩散，所以 `now` 比 `next` 更靠近目的 host。

### `CalculateRoutes(n)`

对所有 host 执行一次 `CalculateRoute(host)`。这样可以得到全网节点到每个 host 的路由。

### `SetRoutingEntries()`

把 `nextHop` 中的“下一跳节点”转换为“出端口编号”，并写入实际转发表。

对 switch：

```cpp
SwitchNode::AddTableEntry(dstAddr, interface);
```

对 host：

```cpp
RdmaHw::AddTableEntry(dstAddr, interface);
```

如果某个目的有多个候选出端口，switch 后续会用 ECMP hash 选择一个。

### `TakeDownLink()`

模拟链路故障。它会：

1. 检查链路是否已经 down。
2. 在 `nbr2if` 中把双向链路标记为 down。
3. 清空 `nextHop`。
4. 基于新拓扑重新计算路由。
5. 清空所有 switch 和 host 的旧路由表。
6. 调用两端 `QbbNetDevice::TakeDown()`，关闭设备并清理队列。
7. 重新安装路由表。
8. 对所有 host 调用 `RedistributeQp()`，重新分配已有 QP。

### `get_nic_rate()`

找到第一个 host，返回它的 `Device(1)` 的链路速率，单位 bit/s。代码默认所有 host NIC 速率相同。

## main 流程

### 1. 记录程序开始时间

```cpp
clock_t begint, endt;
begint = clock();
```

最后会用 `endt - begint` 打印程序运行耗时。

### 2. 读取配置文件

普通模式下，程序要求命令行传入配置文件：

```text
argv[1] = config 文件路径
```

配置文件由大量 `key value` 组成。代码通过一长串 `if / else if` 判断当前 key 是什么，并读取对应的值。

每轮 while 只读取一个 key，所以即使配置文件中同时出现 `ENABLE_QCN` 和 `USE_DYNAMIC_PFC_THRESHOLD`，它们也会在不同轮循环中分别生效。

### 3. 配置 QbbNetDevice 默认属性

```cpp
Config::SetDefault("ns3::QbbNetDevice::PauseTime", ...);
Config::SetDefault("ns3::QbbNetDevice::QcnEnabled", ...);
Config::SetDefault("ns3::QbbNetDevice::DynamicThreshold", ...);
```

这些属性会影响后面创建的所有 QbbNetDevice。

### 4. 配置 INT / TS / PINT 头

根据 `cc_mode` 选择额外头部：

- `cc_mode == 7`：Timely，使用 TS 时间戳。
- `cc_mode == 3`：HPCC，使用完整 INT。
- `cc_mode == 10`：HPCC-PINT，使用 PINT。
- 其他：不使用额外头。

PINT 模式下还会根据 `pint_log_base` 计算 PINT 字段需要的 bit/byte 数。

### 5. 打开输入文件

打开：

- topology 文件。
- flow 文件。
- trace 文件。

并读取：

```text
topology: node_num switch_num link_num
flow:     flow_num
trace:    trace_num
```

### 6. 创建节点

topology 文件会列出 switch 的节点编号。代码先默认所有节点都是 host，再把 switch id 标成 `1`。

创建时：

- host 创建普通 `Node`。
- switch 创建 `SwitchNode`，并设置 `EcnEnabled`。

### 7. 安装 InternetStack 和生成业务 IP

所有节点安装 InternetStack。然后对 host 生成 `serverAddress`，用于 RDMA 业务流。

### 8. 创建链路

对 topology 文件中的每条链路：

1. 读取 `src dst data_rate link_delay error_rate`。
2. 设置 QbbHelper 的 DataRate 和 Delay。
3. 设置链路错误模型。
4. 调用 `qbb.Install(snode, dnode)` 创建两端 QbbNetDevice 和 QbbChannel。
5. 如果端点是 host，给它添加 `serverAddress`。
6. 填充双向 `nbr2if`。
7. 给链路自动分配 `10.x.x.x` IP。
8. 绑定 PFC trace。

### 9. 配置交换机 MMU

对每个 switch 的每个端口：

- 根据链路速率配置 ECN 阈值 `kmin/kmax/pmax`。
- 根据链路速率和传播时延估算 headroom。
- 设置 PFC 动态阈值参数 `pfc_a_shift`。
- 配置端口数和总 buffer 大小。

### 10. 安装 RDMA driver

对每个 host：

1. 创建 `RdmaHw`。
2. 写入拥塞控制相关属性。
3. 创建 `RdmaDriver`。
4. 把 `RdmaDriver` 聚合到 Node 上。
5. 初始化 RDMA 与 QbbNetDevice 的回调关系。
6. 绑定 QP 完成回调 `qp_finish()`。

### 11. 配置 ACK 优先级

根据 `ACK_HIGH_PRIO`，决定 ACK/NACK 是否走高优先级队列。

### 12. 计算路由、RTT 和 BDP

先调用：

```cpp
CalculateRoutes(n);
SetRoutingEntries();
```

然后根据 `pairDelay`、`pairTxDelay`、`pairBw` 计算所有 host pair 的：

- RTT。
- BDP。
- 全局最大 RTT。
- 全局最大 BDP。

### 13. 配置 switch 的拥塞控制模式

把 `cc_mode` 和 `maxRtt` 设置到所有 switch 上。

### 14. 配置 trace

从 trace 文件读取要追踪的节点编号，打开 trace 输出文件。若 `ENABLE_TRACE=1`，则绑定 Qbb 包级事件 trace。

同时向 trace 文件写入 `SimSetting`，包括端口速率和 `maxBdp`。

### 15. 初始化 flow 端口号并调度 flow

每对 host 的源端口从 `10000` 开始递增。

读取第一条 flow，然后根据它的 `start_time` 调度 `ScheduleFlowInputs()`。

### 16. 调度链路故障和队列监控

如果 `LINK_DOWN` 启用，会在 `2s + link_down_time` 时触发 `TakeDownLink()`。

队列监控会在 `QLEN_MON_START` 时启动，并周期性采样到 `QLEN_MON_END`。

### 17. 运行仿真并收尾

```cpp
Simulator::Stop(Seconds(simulator_stop_time));
Simulator::Run();
Simulator::Destroy();
```

仿真结束后关闭 trace 文件，并打印程序运行耗时。

## 输出文件

常见输出包括：

- `FCT_OUTPUT_FILE`：每条 flow/QP 的完成时间。
- `PFC_OUTPUT_FILE`：PFC pause/resume 事件。
- `TRACE_OUTPUT_FILE`：包级 trace 和仿真端口速率元信息。
- `QLEN_MON_FILE`：交换机端口队列长度分布。

## 阅读代码时的核心理解

可以把这个文件分成四层：

1. 输入层：配置、拓扑、流量、trace。
2. 建模层：Node、SwitchNode、QbbNetDevice、QbbChannel、RdmaHw。
3. 控制层：路由计算、ECMP、PFC、ECN、RDMA 拥塞控制。
4. 调度层：flow 启动、链路故障、队列监控、Simulator::Run。

只要抓住这条主线，`third.cc` 的大部分代码都能归到对应阶段。
